# 自有软件更新渠道实现与交付边界

日期：2026-11-27。固定客户端基础提交：a0c0963c483fc8f1aeed4547787d1673adcb583c。
本文件记录已批准产品基线中“自有更新渠道”的代码实现，不替换需求、技术基线或真机验收。

## 发现与处理

原版软件检查地址、发布仓库、签名软件标识和下载页均指向上游产品。仅更换产品名称会留下两类问题：被识别为定制客户端后更新检查与界面入口被隐藏；自动更新链仍信任上游产品的安装包。为保留本产品更新能力并防止被上游安装器覆盖，本轮增加独立的软件更新信任配置。

三个远控服务器档案使用同一软件更新渠道。切换官方服务器只改变远控环境，不改变本软件的发布者或更新公钥。

## 公开构建参数

| 参数 | 含义与约束 |
|---|---|
| BK_REMOTE_UPDATE_CHECK_URL（最新版本文档地址） | 必须为安全超文本传输地址，不带账号、密码、查询或片段；缺失时不发更新请求 |
| BK_REMOTE_UPDATE_REPOSITORY（发布仓库） | 固定的所有者/仓库；缺省为用户现有 beyondchenlin/rustdesk 仓库；拒绝上游 rustdesk/rustdesk 仓库 |
| BK_REMOTE_UPDATE_KEY_ID（更新签名公钥标识） | 缺省 bk-remote-ed25519-main；只允许明确的字母、数字、点、下划线和连字符 |
| BK_REMOTE_UPDATE_PUBLIC_KEY（更新签名公钥） | 规范标准编码的 32 字节 Ed25519（公钥签名）公钥；不包含签名私钥 |

这些是构建期公开参数，独立于设备识别服务公钥、账号会话和配置导入签名。没有取得真实发布材料时，不生成占位私钥或冒充正式公钥。

当前本地候选未配置正式软件更新地址和更新签名公钥。界面明确显示未配置并保留原有更新开关；不能据此声称正式更新服务已部署。

## 发布文档契约

检查端使用只读获取请求，最新版本文档只包含 url（发布页地址）字段。地址必须精确位于所配置仓库的 releases/tag（发布标签）路径，版本采用三个数字段，允许前置字母 v。校验禁止其它仓库、凭据、额外端口、编码路径片段、路径跳转、查询或片段。响应限制为 16 KiB（千字节）；请求有明确超时；跳转后的地址不一致会被拒绝。

对桌面安装更新，发布资产中必须包含 bk-remote-update.json（签名元数据）及其 .sig（签名包络）文件。复用上游元数据结构和严格校验器，软件标识 app（应用）和 package_id（软件包）都必须为 bk-remote。

元数据保留以下字段：schema_version（结构版本）、app（应用标识）、package_id（软件包标识）、version（显示版本）、release_id（发布标签）、published_at（发布时间）、signature_key_id（签名公钥标识）、artifacts（产物列表）。每个产物包含平台、架构、格式、完整地址、纯文件名、字节数及 SHA-256（文件摘要）。平台/架构/格式必须恰好匹配一个产物。

签名包络结构版本为 1，算法为 ed25519（公钥签名），包含公钥标识和规范编码的 64 字节签名。签名输入是以下用途文本的原始字节（末尾一个换行符），随后直接追加元数据文件的原始字节：

```
BK Remote update metadata v1\n
```

上段反斜线与字母 n 表示一个换行符，不是两个需要签名的字符。不得先解析再重新序列化元数据后验签。任何空白、编码或字节变化都需要重新签署。

下载地址必须精确等于所配置仓库、已验证发布标签的下载前缀加纯文件名。直接下载入口也使用同一仓库约束。正常软件更新只接受高于当前显示版本的产物；需要人工回滚时，使用已归档、已核验的安装包和独立回滚流程。

安卓保留原版通过发布页获取安装包的方式，链接改为本产品发布页；安装与升级仍由安卓系统处理签名及用户授权，不增加后台静默安装。

## 保留的原版行为

- 保留检查更新及自动更新设置，不改变全局定制客户端判定和原有默认设置保存语义。
- 保留远控活动会话期间不进行自动安装的检查。
- 保留严格证书校验、代理配置、下载超时、元数据大小上限、文件大小与哈希核验。
- 保留安装前复制到受保护位置并再次校验的流程。
- 原上游检查与验签实现保留用于上游维护；当前产品入口使用自己的信任配置。
- 未配置或检查失败会清除待更新地址，不回落上游产品的安装包。
