# BK Remote 技术基线第二轮审查

**审查范围：** 身份认证、密钥、数据隔离、生命周期、动态中继、构建和回滚。  
**审查结论：** 安全与运维门禁已明确；仍有 5 项外部输入需在正式打包前确认。

## 1. 安全审查

| 编号 | 检查点 | 结论与门禁 |
|---|---|---|
| R2-01 | 公众注册 | app.register=false；启动检查和未认证请求测试必须证明注册关闭 |
| R2-02 | 首次管理员 | 不允许数据库迁移自动生成默认管理员；bootstrap-admin 仅在没有管理员时执行一次 |
| R2-03 | 设备归属 | 不以设备编号、公开 sysinfo 或 UUID 单独授权；必须验证设备公钥持有证明 |
| R2-04 | 部署令牌 | 原子消费、短时有效、绑定账号和设备、同设备重试幂等；过期/已用/跨账号均拒绝 |
| R2-05 | 固定密码 | 不写地址簿同步、API 响应、日志、截图和普通配置；不跨主控端同步明文 |
| R2-06 | JWT（身份令牌） | 高熵密钥只保存在服务端；不打包到客户端；首版不启用服务端强制登录门禁 |
| R2-07 | 定制配置签名 | 私钥离线保存；客户端仅内置公钥；篡改配置、未知公钥必须拒绝 |
| R2-08 | 账号服务暴露面 | 不部署 rustdesk-api-web；web-client=0、show-swagger=0；仅开放必要 API |

## 2. 生命周期与网络可靠性审查

- Android（安卓）主动停服必须写入持久化停止意图；开机接收器检查停止标记。
- 屏幕采集停止与整个接收服务停止分开；所有整服务停止入口统一二次确认。
- Android 系统授权撤销、锁屏、重启不允许被标记成“仍已授权”。
- 中继节点先探测后发布；配置原子写入；运行时更新后回读；失败恢复上一版本。
- 127.0.0.1:21115 仅供本机命令使用，不映射公网，不由未认证 API 代理调用。
- 全节点故障时保留上一配置并显示降级，不伪报新节点健康。
- 现有 hbbs 多节点策略为轮询，不宣称按最低延迟择优。

## 3. 数据隔离审查

服务器档案切换必须隔离账号令牌、地址簿、设备身份及本机保存的连接凭据。仅更换 ID Server 或 API Server 地址而继续复用同一令牌/地址簿，不满足 PRD。APP_NAME 可以隔离 BK Remote 与官方客户端，但 BK Remote 内部三种档案仍需独立命名空间。

## 4. 构建与交付审查

- Flutter 3.44.1、Dart 3.12.1、Java 17.0.21、Go 1.26.4、Rust 1.98.1 均已找到。
- Windows Build Tools 2022 检查通过。
- Android SDK 已有 Android 35 与 Build Tools 35.0.1，但 Flutter Doctor 缺 cmdline-tools；ADB 当前没有连接真机。
- 不升级共享 Flutter SDK；不覆盖 BK CAT/BKCLAW SDK。
- 当前 C/D/E 可用空间为 41.3/59.0/32.8GB，未达到每盘 50GB 目标；不在 C/E 安装大体积 SDK，不擅自删除项目文件。
- 代码审查、单元测试、双端构建、真机 E2E（端到端）和签名哈希验证必须留证据；模拟结果不能替代真机。

## 5. 正式交付前待确认

1. 正式自建域名、API 地址、服务器公钥及证书。
2. Android applicationId（安卓应用标识）。
3. 两份 BK REMOTE 原始标志中哪一份作为唯一主标。
4. 可连接的 Android 真机及其系统版本。
5. 正式签名密钥的安全保存位置与备份责任人。

以上项目不阻止本地代码开发；在确认前不生成正式签名安装包、不部署生产。

**第二轮结论：通过。技术基线可作为实施依据；未完成的安全门禁必须在对应阶段通过后才能进入下一阶段。**
