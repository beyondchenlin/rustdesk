# BK Remote（内部远程维护系统）
## 产品需求文档（PRD）｜1.0 评审稿

**版本：** 1.0　　**日期：** 2026-11-26（北京时间）

**适用范围：** Windows（微软桌面系统）客户端、Android（安卓）客户端、自建账号与设备服务、中继配置管理。

**文档状态：** 已完成两轮需求评审并吸收修订，待用户最终确认；本版仅为需求基线，未实施产品开发、打包、提交或生产部署。

**核心参考项目（用户指定）：** https://github.com/nntu/rustdesk

**唯一实施原则：** 保留 RustDesk（远程桌面控制软件）原有功能与原生远控机制；只改变默认配置、品牌、部分入口位置，增加团队账号、设备同步和动态中继管理能力。本期不开发网页远控端，不重构原版控制界面，不重新发明远控协议。

## 1. 产品定位与需求边界

### 1.1 背景与目标

PIGEON-BKCLAW（群控系统）负责日常自动化任务，BK Remote（内部远程维护系统）提供独立的人工维护通道。当群控网页、任务队列或手机自动化进程出现故障时，团队人员通过原生客户端直接连接自己的安卓手机和电脑，查看实时画面、操作并修复故障。

已有基础：香港自建 RustDesk 开源服务端 1.1.16 已完成单设备实际远控验证（用户确认）；此前已建立客户端与服务端派生仓库。当前验证不等于长时间运行、多人权限、设备同步及中继切换全部验收通过。

|---|---|---|

**本期不做：** 网页远程画面及控制端、独立网页管理控制台、完整 STF（智能手机测试农场）前端还原、重复开发群控任务队列、重新部署完整 STF 服务栈、购买 RustDesk Pro（专业版）、新增其他操作系统客户端。原版已具备的功能不因暂不新增而被删除；首版管理员通过受保护的命令行工具和已认证管理接口完成账号及中继管理。之前讨论的网页一比一还原方案已由用户后续决策替代，不能作为本期验收条件。

### 1.3 成功标准

安装 BK Remote → 完成授权和设备固定密码设置 → 登录自建账号 → 两端同步团队设备 → 选择授权设备建立原生远控 → 断开后继续在线待命；管理员集中修改中继后，后续连接采用新中继，无须逐台改配置或重装。无权设备不能因知道编号或账号名称而获得管理权限。

## 2. 使用角色与产品体验

| 角色 | 职责与权限 |
|---|---|
| 团队管理员 | 通过受保护的命令行工具/管理 API 创建账号、批准设备加入、管理设备分组、重置账号、撤销设备、管理中继并审计 |
| 授权操作员 | 登录团队账号，查看有权设备，按授权连接；首次连接仍需目标设备固定密码或本机已安全保存的凭据 |
| 被控设备使用者 | 首次授权、检查当前服务及连接状态；随时撤销系统权限、结束连接或停止服务 |

首版支持同一个 BK Remote（内部远程维护系统）账号在多台授权设备同时登录，并同步该账号有权访问的设备清单。团队管理员可创建多个独立成员账号并分配设备权限；不开放公众自助注册。一个账号可以多端登录，但账号登录只证明管理身份，不自动共享目标设备固定密码，也不绕过原生远控验证。

### 2.1 电脑端

沿用原版首页、设备卡片/列表、搜索、最近连接、收藏、发现设备、地址簿、远控窗口和设置。新增或复用“我的设备”视图作为账号已绑定设备的统一入口，支持设备名称、平台、分组、在线状态、最后在线、连接及原有操作菜单。保留原版多窗口、多会话与工具栏，不新增实时监控墙或同步群控。

### 2.2 安卓端

保留原版连接、屏幕共享、消息、设置等入口；默认配置在首次使用时完成。共享页面展示设备编号、连接及授权状态，避免把停止服务放在高频操作位置。设备列表支持选择其他已授权手机或电脑进行远控。安卓端按原生会话模型使用，首版不承诺像电脑端一样并行显示多个实时画面。

### 2.3 状态定义

| 状态 | 显示依据 | 不允许的行为 |
|---|---|---|
| 在线待命 | 设备身份已验证；连接/心跳有效；无活动维护会话 | 不持续推流或自动录制 |
| 可远程控制 | 在线且必要屏幕/输入能力有效 | 不用单一在线位推断所有权限有效 |
| 需现场授权 | 权限缺失、被撤销或系统要求重新授权 | 不自动批准系统弹窗，不伪造已授权 |
| 维护中 | 实际会话建立，连接方与会话标识可追溯 | 不将连接请求误标为成功 |
| 离线／未知 | 超过心跳有效期或状态查询失败；显示最后确认时间 | 查询失败不能伪造在线或永久离线 |
| 已解绑／暂停 | 已确认的管理操作及设备实际执行结果 | 不自动恢复用户明确停止的服务 |

## 3. 原生能力与默认配置契约

### 3.1 原有功能保护

开发前必须以固定的客户端提交建立原生功能清单、双端菜单清单及对照测试。原有直接输入设备编号连接、收藏、最近记录、局域网发现、地址簿、账号登录、密码/点击/混合验证、画质、显示缩放、编码器、剪贴板、文件传输、聊天、声音、录屏、终端、端口转发、多显示器等功能，凡原版本和目标平台支持的均保留。某平台未实现的原生能力不能以另一平台的功能冒充。

| 配置或入口 | 新安装默认值 | 兼容及约束 |
|---|---|---|
| 接受连接 | 仅密码验证 | `approve-mode=password`（密码验证）；仍可切换点击或混合验证 |
| 验证方式 | 仅固定密码 | `verification-method=use-permanent-password`（固定密码）；临时密码及组合模式仍可选 |
| 固定密码 | 每台设备独立随机生成或受控设置 | 首次初始化后安全保存；不得写入通用安装包、普通地址簿字段或日志；主控端可在本机安全存储中记住 |
| 屏幕捕获 | 默认建议启用 | 实际状态以系统授权为准；授权撤销后标记需现场授权 |
| 输入控制 | 默认允许 | `enable-keyboard`（输入控制）；安卓无障碍必须由用户在系统设置确认 |
| 文件传输 | 默认允许 | `enable-file-transfer`（文件传输）；安卓仅限应用工作区及明确授权目录 |
| 剪贴板 | 继承原版默认值 | 用户可关闭；不记录剪贴板内容 |
| 音频、录像等 | 保留原版功能及各自设置 | 自动会话录像不默认开启；音频权限按需申请，不扩大授权 |
| 开机及后台 | 引导启用；经授权后配置 | Windows（微软桌面系统）正式安装并启动系统服务；安卓遵循系统与厂商限制 |
| 画质与性能 | 建议先使用反应速度优先，或自定义码率 25%、15 帧/秒测试 | 非已验证最优值；原有自动、平衡、高清等选择保留；真实分辨率缩放须单独验证 |
| 停止服务 | 设置页末尾，明确确认 | 现有停止逻辑不删除；仅调整位置并防止其他开关误触 |
| 同账号多端 | 设备列表及授权关系同步 | 不自动同步目标设备固定密码；跨主控端免输入需端到端加密凭据库，首版不做 |
| 登录强制策略 | 首版 hbbs MUST_LOGIN=N（关闭） | 保留原生无账号手动连接；账号服务认证控制团队设备登记/地址簿。启用 Y（开启）会拒绝无有效令牌的连接，须单独评审 |

默认值仅用于新安装或首次加入团队时的明确初始化。不得每次启动、升级或服务器切换都覆盖用户已修改的选项；不使用最高优先级的强制覆盖来伪装默认值。系统撤销权限、用户选择停止服务，优先于产品默认值。

### 3.2 固定密码和账户密码分离

账号登录密码用于管理身份；设备固定密码用于原生远控握手，两者不得混用。推荐设备固定密码至少 16 位随机强密码，长度以固定客户端版本兼容性测试为准；按设备独立生成。禁止全员、全设备共用安装包内置密码。密码不得出现在普通列表、日志、截图或明文配置下发中。

密码设置与连接流程：由被控设备本地初始化或管理员通过受保护流程设置；主控端首次连接仍按原生流程输入目标设备固定密码，用户可选择在该主控端的系统安全存储中记住，后续在该主控端一键连接。账号登录和地址簿同步不等于远控密码同步。首版不通过参考项目的 AddressBook.Password（地址簿密码）字段同步明文密码；跨主控端免输入需要端到端加密凭据库、成员撤销和密钥轮换设计，列为后续增强。

### 3.3 首次初始化与权限管理

1. 安装正式签名客户端；展示品牌、用途、授权对象和隐私说明，确认仅用于自有或明确授权设备。
2. 载入 BK Remote（内部远程维护系统）默认服务器档案；检测自建服务可达性和公钥匹配，显示设备编号。
3. 引导用户登录/绑定团队账号并完成设备登记；Windows（微软桌面系统）可评估复用参考项目的一次性部署脚本；Android（安卓）必须实现应用内登录后的授权登记流程，不假设 Windows（微软桌面系统）脚本可用于手机。设置本机固定密码；未绑定团队账号时保留原生手动连接能力。
4. 逐项引导系统授权：屏幕捕获、无障碍输入、文件工作区或选定文件夹、通知及必要后台运行权限；未授权项目可跳过或稍后补齐，状态真实显示。
5. 用户确认后启动接收服务；设备登记必须使用已认证的账号令牌或短时一次性部署令牌，并校验设备唯一身份及公钥证明。登记成功后进入在线待命。不得把公开的 /api/sysinfo（设备信息上报）请求、设备编号或未经验证的 UUID（通用唯一识别码）单独作为设备归属证明。下次启动只检查失效项，不重复弹出已有效授权，不自动代用户确认。

安卓安装阶段不能静默取得无障碍和屏幕捕获授权。安卓 14 及以上每次新建屏幕投影会话需要用户同意；有效投影可按上游机制复用，不能承诺权限被系统撤销、重启或锁屏后仍无需现场操作。面向安卓 15 及以上的应用不能从开机完成广播启动媒体投影前台服务；安卓 15 季度平台更新第 1 版及以上锁屏会自动停止屏幕投影。以设备实测结果为准，保留可见系统通知及用户主动停止能力。[S5、S6]

### 3.4 防误触与服务生命周期

共享页面以状态、授权修复及连接信息为主。将“停止远程服务”放在“设置 → 远程维护 → 底部危险操作”；触发时显示“停止后本机将不能接受远程维护，需重新启动”，默认选择取消。同步检查共享页面的屏幕捕获开关及其他调用相同停止方法的入口，不能只移动一个按钮而保留无提示停服路径。单次会话断开按钮、系统停止共享、用户撤销权限始终保留且可访问。

区分退出界面、结束当前会话、停止整个接收服务、关闭开机启动。首版只实现并验收固定上游版本实际存在的生命周期入口；“暂停接收但保持在线”等新状态先列为增强，不作为已经存在的原生能力。停止后持久化用户意图，不由后台重试或策略强行重新启用；用户主动恢复后才重新监听。会话结束释放视频与音频采集资源；无会话不持续传输画面，不额外获取内容。

## 4. 服务器档案与动态中继

### 4.1 保留三种服务器模式

| 模式 | 默认及配置规则 |
|---|---|
| BK Remote（内部远程维护系统） | 新安装默认；预置自己的稳定设备识别域名、服务器公钥、账号服务地址；中继使用“跟随服务器”，客户端 relay-server（中继服务器）字段留空，由 hbbs 下发 |
| 官方公共服务器 | 原生入口完整保留；选择后恢复官方默认配置及其独立账号环境 |
| 手动自建 | 保留设备识别、中继、账号服务、公钥原输入框及导入导出；手动配置优先，不被团队同步覆盖 |

各档案分别保存，切换时明确展示目标、断开/重新建立必要的服务连接并验证新配置；保存失败恢复原档案，不默默退回官方公共服务器。不同服务器环境下的账号、地址簿、设备标识和凭据分区保存，防止串用或泄漏。默认不屏蔽原版网络设置入口。

现有单机验证基线：设备识别地址 `47.242.93.105`（网络地址），中继 `47.242.93.105:21117`（测试地址），账号服务尚未部署。服务器公钥采用现有自建服务对应的公钥，发布前从受控部署读取并核对；禁止打包私钥。生产安装包建议使用自有稳定域名；域名和账号服务实际地址在开发前确认，不把尚未配置的示例地址写入正式安装包。

### 4.2 设计原则：管理分配，不再多加一层视频转发

**控制端与被控端 → hbbs（设备识别及连接协调服务）协商 → 优先点对点直连；直连失败时双方连接同一个 hbbr（画面中继服务）。** 账号服务负责管理信息，不经过它传输视频。管理员只修改中继节点池，客户端无需知道其他节点或逐台更新。

已核对服务端 1.1.16 的 `src/rendezvous_server.rs`：支持 `-r / --relay-servers`（中继列表）、本机运行时更新 `relay-servers/rs`（中继管理命令）、多节点轮询；多节点时约 3 秒执行连接探测。客户端优先使用手动填写的中继，否则采用服务端提供的地址，最后才按默认端口推导。因此团队自动模式底层中继字段应为空，界面显示“自动分配（当前连接节点）”，不能把固定中继网络地址作为永久客户端默认值。[S1、S2、S3]

### 4.3 集中中继管理

| 管理能力 | 首版要求 |
|---|---|
| 节点登记 | 名称、地址及端口、区域、启用状态、配置版本；仅管理员操作 |
| 健康检测 | 检查协议可达、公钥/认证兼容性、真实测试连接；基础 TCP（传输控制协议）探测不等于线路质量 |
| 切换发布 | 新节点先验收、原子保存候选配置，同时更新持久化启动配置与运行时列表；读取实际列表确认后再标记生效 |
| 持久化 | 更新启动配置及变更记录；服务重启不能丢失当前有效配置；并发变更按版本校验 |
| 回滚 | 保留上一有效节点池；新节点失败则撤销发布、恢复并重新检测 |
| 会话保护 | 已建立的连接不强制迁移；新连接使用新节点；故障中断后重新连接 |
| 管理入口 | 首版采用受保护的服务器管理命令或内部管理接口；不新建网页控制端，不公开回环管理端口 |
| 全节点故障 | 显示无健康中继/配置降级；禁止把旧节点误报健康；保留上一配置供恢复并告警，不宣称自动容灾 |

开源服务端现有多中继选择是轮询，而非按每个设备延迟择优；检查主要验证 TCP（传输控制协议）可连接，不代表实际线路质量。服务端 1.1.16 在所有候选节点均检测失败时不会用空列表覆盖最后一组可用列表，可能留下已过期节点。首版管理层必须显示“无健康中继/当前配置降级”，禁止把旧节点误报为健康；新列表至少有一个真实验证通过节点才能发布。若全部节点失败，保留上一次配置供恢复和告警，不宣称自动容灾；点对点直连仍按原生机制尝试。自动线路质量评分、按设备地域择优列为后续增强。

### 4.4 设备识别服务器整体迁移

仅更换中继无需改变设备识别服务、公钥及客户端账号配置；如更换整个识别服务器，使用稳定域名解析（DNS，域名系统）、持久化的原有服务器密钥及登记数据库进行受控迁移，保留旧节点和回滚方案，避免新旧登记库分裂。中继节点按同一服务身份安全配置，私钥按最小范围管理。域名缓存、客户端重连与会话断开均需验证，不承诺秒级无感迁移。独立签名配置清单和备用获取地址作为后续整站容灾方案，不在首版强行引入；如启用，必须具备签名、公钥信任、版本防回退、失败回滚和手动模式不覆盖。

## 5. 自建账号、设备同步与互控

### 5.1 账号存放与注册方式

所有 BK Remote 账号及设备管理数据保存在自己部署的独立账号服务和数据库；不向官方账号系统提交团队密码或设备列表。原版客户端保留官方登录能力，但仅在明确选择官方环境时使用。

现有开源识别/中继服务不包含完整账号与云端地址簿服务。原版设置中存在 API（应用程序接口）服务器字段和登录界面，登录是否可用由配置的账号服务决定。自建模式若未填写该字段，客户端会按上游规则从自建识别服务器推导地址；不能把登录按钮存在误认为已部署账号数据库。[S1、S4]

首版不对公网开放自助注册。参考项目 app.register（是否开放注册）必须显式设为 false，并在启动检查及未认证注册请求测试中确认；其 /api/admin/user/register（管理员注册路由）位于后台认证中间件之前，不能仅依赖前端隐藏注册按钮。初始管理员创建必须通过新实现的一次性本机 bootstrap（初始化）命令或等价离线初始化步骤，完成后立即关闭并留下审计；参考项目未证明已有可直接复用的安全 CLI（命令行工具）。普通账号由已认证管理员通过受保护的管理 API（应用程序接口）或内部命令创建；首版不做邀请链接。账号服务不可用时，团队设备列表显示缓存及最后同步时间；原生手动连接仍可按目标设备固定密码使用。首版 hbbs（设备识别服务）不启用 MUST_LOGIN=Y（强制登录），以保留原生无账号手动连接能力；如果以后启用，所有无有效 API 令牌的连接请求会被拒绝，必须作为单独策略变更评审。

### 5.2 设备登记与同账号互控

设备加入流程：客户端登录 → 本机用户明确同意加入 → 客户端使用账号访问令牌或短时一次性部署令牌调用受保护的设备登记接口 → 服务端校验账号权限、设备 UUID（通用唯一识别码）、公钥及绑定冲突 → 创建/更新归属关系 → 拉取有权设备清单。设备 ID（设备编号）仅作为索引，不是授权凭据。nntu 参考项目的 Windows（微软桌面系统）部署脚本不能替代 Android（安卓）端流程；安卓首版必须完成独立的端内登记和真机验收。

同账号已授权设备可以互相发现并发起原生远控，支持电脑控制电脑、电脑控制安卓、安卓控制电脑、安卓控制安卓四种方向，逐项真实验收。连接仍执行目标设备固定密码认证；同账号不等于自动绕过固定密码。首版首次连接可逐台输入目标设备密码，并在当前主控端安全保存；不同主控端之间不承诺自动同步密码。首版保留原生多设备列表、桌面多会话，安卓并行控制以实际原生能力为准。未授权设备不出现在团队列表；离线设备保留档案，标明最后在线时间。设备名称、分组、收藏/备注的同步冲突按服务端版本解决，避免重复设备和覆盖本地用户设置。

### 5.3 权限与解绑语义

账号登录不取代设备固定密码，也不绕过系统授权。服务端必须校验设备归属、请求者权限和设备证明，防止任意编号冒领、跨账号越权和重放。团队设备可互相连接的授权范围由账号与设备所属关系控制；已登录并取得有效远控凭据的主控端才允许发起受管理连接。

管理层撤销账号/设备应使账号令牌失效、从授权列表移除并记录审计。注意：原生远控密码独立存在，仅移除地址簿不会撤销已经知道密码的连接方。真正撤销远控访问需对目标设备执行凭据轮换或停用接收并验证结果，清除本端已保存凭据；离线设备标记“待撤销”，不能报成功。更细粒度的受管理会话强制授权可评审签名会话授权方案，但不得以可伪造的设备编号白名单代替认证，不得破坏显式手动/官方原生模式。

### 5.4 数据与接口需求

| 数据实体 | 必需信息（最小化采集） |
|---|---|
| 团队账号 | 账号唯一标识、密码哈希、状态、角色、创建及更新时间 |
| 设备 | 设备唯一标识、远控编号、服务器身份域、本机身份公钥或证明、平台、名称、版本、最后心跳 |
| 绑定与授权 | 账号/设备关系、分组、授权范围、状态、批准与撤销时间 |
| 会话 | 会话唯一标识、双方设备、连接方式、开始/结束、结果、线路；不默认存储画面或输入内容 |
| 中继节点及版本 | 节点名称、地址、健康、启用/排空状态、配置版本、变更人及回滚信息 |

优先兼容原版登录和地址簿契约，例如 `/api/login`（登录）、`/api/logout`（退出）、`/api/currentUser`（当前用户）、`/api/ab`（地址簿）、`/api/ab/personal`（个人地址簿）、`/api/heartbeat`（心跳）、`/api/devices/deploy`（设备登记）。其中 `/api/devices/deploy` 必须使用有效用户令牌或短时一次性部署令牌；参考实现的部署令牌有效期为 30 分钟且一次性使用。公开的 `/api/sysinfo`（设备信息上报）在参考项目中可创建未归属设备记录，不得用它作为可信设备绑定入口。实际字段、请求方法及授权模型须根据固定客户端提交做契约测试后冻结；不得仅因参考项目有同名接口就视为兼容。设备管理、策略、审计采用独立职责边界。所有接口要求身份认证、授权校验、参数检查、幂等、错误码和日志脱敏。

| T16 账号注册与设备归属 | app.register=false（关闭注册）生效；未认证注册请求被拒绝；公开 sysinfo（设备信息上报）产生的未归属设备不进入团队列表；只有受认证 deploy（登记）可绑定设备 |
| T17 安卓设备登记 | 安卓端登录后使用有效令牌完成本机登记；设备 UUID（通用唯一识别码）/公钥冲突、重复提交、令牌过期、解绑和重装恢复均有真实结果 |
| T18 原生手动连接兼容 | 首版 MUST_LOGIN=N（关闭）时，未登录账号的原生手动连接仍可按目标设备固定密码完成；如启用 MUST_LOGIN=Y（开启），必须记录其对手动连接的限制并重新确认 |
| T19 密码与地址簿安全 | 地址簿同步负载、数据库、日志、网络抓包中均不出现明文设备固定密码；不同主控端首次连接按原生密码流程，不伪称密码已同步 |
| T20 强制登录令牌兼容（条件项） | 若未来启用 MUST_LOGIN=Y（强制登录），验证客户端从账号服务获取/刷新 JWT（身份令牌），并在 PunchHoleRequest（连接请求）及 RequestRelay（中继请求）中携带；服务端拒绝空令牌、过期令牌和错误签名。首版不启用 |
